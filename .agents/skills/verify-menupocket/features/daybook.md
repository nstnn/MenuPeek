# Daybook task window

Today and Later use the Daybook layout: a warm Light/Dark paper canvas, System Monospace date rail and heading, a quiet paper Today/Later switch, flat task groups and subtle row rules. All app-owned text uses System Monospace, including task text, placeholders, popovers, History, Categories, Settings, Quick Add, menu bar count, menus and drag previews. Font sizes, weights and italic emphasis are retained. Existing add/edit/cancel, actions, movement, History and Settings behavior stays intact. The shared rail keeps today’s date, explicitly labeled Today progress, and navigation in the same positions on Today, Later, History, Categories, and Settings. Later’s main content remains undated.

## Sub-features

- `daybook-layout`: initial 1000 × 700 pt and minimum 800 × 560 pt content; both retain the full 218 pt rail. The compact layout remains a defensive fallback below 740 pt width or 480 pt height.
- `daybook-canvas`: Today, Later, History (including Unfinished and its day detail), Categories and Settings share `DaybookPalette.canvas` in Light and Dark. The rail retains its separate paper color; inset cards retain their own surfaces. Capture all five destinations in each theme and compare unobstructed main-pane background pixels, including the Settings heading and footer, so a child view cannot silently cover the shared canvas with a system color. Browsing must leave task/category rows unchanged.
- `system-monospace`: check Today/Later date and headings, draft/placeholder and saved task text, category/action popovers, History, Categories, Settings, Quick Add, count and glance in Light/Dark. Capture screenshots and confirm wider glyphs do not obscure controls; save a fictional task and compare SQLite before/after relaunch. Window chrome and system-owned UI remain managed by macOS.
- `daybook-navigation`: Today/Later in the rail as a quiet paper switch: a faint track, the selected segment a raised thumb (canvas paper in Light, a light wash in Dark) with medium-weight terracotta text, the other segment secondary text that turns primary on hover; the switch fades to 50% while guarded. Accessibility still exposes the native segmented picker (`taskDestination` labeled `Task list`, `todayTab`/`laterTab` radio buttons). The footer lists Calendar, a thin rule, History, Categories and Settings. Calendar, History, Categories and Settings replace only the right detail column; the rail stays visible and interactive. Idle Categories allows navigation away; rename and removal confirmation block it. Settings entry points, including Command-comma, reuse the same task window.
- `daybook-states`: empty, unavailable/Retry, long text, long category, completed, active editor and deletion confirmation.
- `daybook-drafts`: native fields, the Daybook Category capsule and popover, Save/Cancel, Return/Escape, retained drafts and Undo across window reopen.
- `daybook-buttons`: buttons without their own style use `DaybookButtonStyle`. Every button is a capsule. Quiet actions (Cancel, Retry, This month, Calendar's Today, Load more, Done, Rename, Settings actions) have a hairline outline and secondary text; on hover the text turns primary and the outline darkens. One prominent action per view sits on a soft terracotta tint with accent text and fills solid terracotta on hover: composer Save, category Create and rename Save, and History Continue today. Destructive roles swap the accent for red: Remove… is a red row in a category's `…` popover, and the confirming Delete and Remove Category sit on a red tint that fills red on hover. Disabled buttons fade to 40%.

## How to get to it (user POV)

- Open the task window from the menu bar count or app launch.
- Use the rail for Today, Later, History, Categories and Settings.
- Choose Add task or Command-N; use the row ellipsis for Edit, Move and Delete. It opens a Daybook popover (paper card, terracotta hover/keyboard highlight, Delete in red) instead of a system menu.

## Driving it with fixture.sh + mpax

Preconditions:

- Build a fresh isolated fixture and launch with `--seed basic --now 2026-10-22T16:00:00Z --tz America/Toronto` (Thursday, October 22, 2026); doctor must pass. Start with `$F snapshot <run> before-daybook`.
- **Today appearance.** `$F ax <run> value id=daybookDate` exposes the saved civil date (`Thursday, October 22, 2026`). `$F ax <run> value id=todayProgress` exposes `1 of 4 complete` (the visible text is `1/4 done today`). The rail starts with the weekday and date (no app-name label; the window title carries it), the month line reads `October 2026` without a comma, and the main heading is plain `Today` with no eyebrow line (Later: `Later` plus its remaining count). Screenshot the date rail and flat groups with `$F snapshot <run> today-daybook`.
- **Later.** `$F ax <run> press id=laterTab`, then `$F ax <run> wait id=laterTaskList`. `$F ax <run> value id=daybookDate` and `value id=todayProgress` retain the same values and positions as Today. Calendar, History, Categories and Settings remain visible at 14 pt with 16 pt icons in one aligned column, and each row is clickable across its full width. The main pane shows Later and its remaining count. Return with `press id=todayTab`.
- **Add/edit/delete/move.** Follow [Today](today-tasks.md) and [Later](later-list.md) on this build. Snapshot before/after; compare SQLite rows and saved order as well as counts. Test Cancel before any confirmed deletion.
- **Child routes.** `press id=taskHistoryEntry` opens History in the right column; the rail's Today/Later switch remains available. History has no Back button: return with `press id=todayTab`. Pressing History while Later is selected selects Today first, then opens History. `press id=calendarEntry` opens Calendar (see [Calendar](calendar.md)). `press id=manageCategories` opens the Categories pane in the same column (not a sheet); close it with `press id=doneManagingCategories`. `press "label=Open Settings"` opens the Settings pane in the same window: `wait id=settingsContent`, and `windows` still lists one `MenuPocket Tasks` window.
- **Buttons.** With the composer open, `value id=saveTask` reports `[disabled]` until text is typed, and `press id=saveTask` still saves. `press id=cancelNewTask` still cancels. Open a row's Delete… and confirm that `press id=cancelTaskDeletion` keeps the task and `press id=confirmTaskDeletion` removes it from `db.txt`. In History, `press id=historyThisMonth` and `id=continueHistoryTasks` still act. With Tab navigation, Save, Cancel, Delete and Retry still take focus and respond to Space. Screenshot the composer, the deletion confirmation, the category manager and History in Light and Dark; hover appearance needs a pointer and is Not tested through AX.
- **Appearance.** Change Theme through Settings on the isolated fixture only, observing Light and Dark. Restore the fixture setting afterward. Capture both with `snapshot`.
- **Window sizes.** Use actual window-corner dragging through an available native UI adapter to inspect 800 × 560 pt content and 1000 × 700 pt. Confirm an attempted drag below the minimum stops at 800 × 560 pt. The AX driver has no resize command. Record measured window size; do not equate screenshot pixels with AppKit points. Verify draft/category/Save/Cancel and deletion buttons remain reachable, with usable task-list scrolling. Snapshot each size.
- **Persistence.** After intentional fictional task changes, `stop`, `snapshot stopped`, `launch` the same run without reseeding, `snapshot relaunched`. Compare `db.txt`, preferences, saved count and visible rows.
- **Recovery.** Use `fail-open on`, stop/launch, observe Unavailable and disabled Add. Use `fail-open off`, press `id=retryTodayTasks`, and snapshot the recovered list. This is a simulated read failure.

## Gotchas

- The date rail uses the saved civil day key, not a second time-zone conversion. The shared rail always describes Today; Later tasks remain undated and never contribute to Today progress.
- Native checkboxes, text fields and pop-up menus remain native; only the row `…` actions, the composer Category control and the category manager's `…` actions use the custom Daybook popover. The monospaced heading and color palette do not replace keyboard/focus or persistence contracts.
- Add task is replaced by the composer while it is open. Finish or cancel it before locating `id=addTask` again.
- While editing, confirming deletion, renaming or removing a category, or with a Calendar block editor open, destination switches and conflicting actions remain guarded. `value id=todayTab` and `id=laterTab` then report `[disabled]`, and a press leaves the selection unchanged. An idle Categories pane does not disable them: pressing Today or Later closes the pane.
- The Today/Later switch is drawn by `DaybookDestinationControl`; its AX tree comes from `accessibilityRepresentation`, so `frame id=todayTab` is the representation's segment frame, not the drawn thumb. Judge the look from screenshots.
- Browser concept screenshots are design references, not evidence for this native build. Pointer drag behavior, VoiceOver and real system integrations require their own observations.
