# Product requirements

MenuPocket is one local macOS desktop and menu bar app for daily tasks. The desktop increment replaces the compact editable popup with a reusable Today window and menu bar progress. This tracked document defines the product contract without requiring the Git-ignored local plan.

The behavior in the desktop task contract and the rules that follow it is implemented in source. Dated verification results belong in [Desktop regression](DESKTOP_TASK_REGRESSION.md) and [Desktop acceptance](DESKTOP_TASK_ACCEPTANCE.md); implementation, automated verification, and actual system observations are separate claims.

## Desktop task contract

| Requirement | Expected behavior |
| --- | --- |
| REQ-001 — Task window | One resizable task window is reachable from the menu bar and Dock. Repeated presentation restores the same window after closing or minimizing it, including while Settings is open. |
| REQ-002 — Menu bar progress | The saved completed/total count stays visible in the menu bar without an icon while running. A successful empty read shows `0/0`; initial or failed reads show `—`. Successful writes update progress without opening the window; rejected writes retain the last saved count. |
| REQ-003 — Today layout | Show the current local date, progress, tasks, Add task, Settings access, and an informational yesterday count when nonzero. Highlight the yesterday reminder in semibold red so unfinished planned tasks are easy to notice. Tasks stay in creation order, first created first; new tasks append at the bottom. Completion, uncompletion, editing, refresh, and relaunch preserve that order. Deletion closes the gap while keeping the remaining tasks in relative order. Keep empty, all-completed, long-list, long-text, and resized states usable. |
| REQ-004 — Task actions | Add, complete, uncomplete, edit, and delete tasks. Trim input and reject whitespace-only text. Confirm deletion with cancellation available. Publish saved changes only after a successful write; failures retain saved rows/count and recoverable draft text with an inline error. |
| REQ-005 — Daily model | Keep each task's assigned local day. Do not carry unfinished tasks into today. Refresh both surfaces on day, clock, time-zone, and wake changes without requiring an open task window. Yesterday's unfinished count is informational. |
| REQ-006 — Lifecycle | Explicit launch, Dock reopening, and a primary menu bar click show tasks. The app remains in the Dock and Command-Tab. Closing the last window leaves the process and status item running; Quit exits and removes the item. |
| REQ-007 — Login startup | Preserve the existing launch-at-login registration and Settings control. Login launch initializes daily progress without raising task or Settings windows or requesting activation; the Dock icon remains visible. A genuine login requires separate system observation. |
| REQ-008 — Native interaction | Settings is reachable from the task window and native menu. Support keyboard focus, Return to save, Escape to cancel, Command-N to add, Command-comma for Settings, Command-W to close, Command-Q to quit, and native text editing. Clicking noninteractive space in the Today window clears the visible control focus; Tab can focus a control again. |
| REQ-009 — Preservation | Keep existing SQLite tasks, preferences, onboarding state, app identity, and sandbox storage. Category storage preparation introduces additive schema v2: fresh databases and validated unversioned/v1 stores use v2, preserving task UUIDs, rowids/order, text, day keys, timestamps, completion, and counts. Existing tasks have no category association (General). Reject unsupported newer or incompatible schemas without overwriting their data; failed migration rolls back schema, data, and version. |
| REQ-010 — Acceptance | Record automated build/test results separately from actual running-app menu bar, Dock, window, Settings, and system observations. Identify the final source and artifact. Record unavailable checks accurately. |
| REQ-011 — Handoff | Current product/developer docs agree about behavior, scope, implementation, and verification status. Tracked evidence remains understandable without local ignored plans or build artifacts. |
| REQ-012 — Theme | Settings offers System, Light, and Dark in an Appearance section between Startup and App. System is the default and follows the macOS appearance, so an existing install looks unchanged until a choice is made. A choice applies to every app window immediately, is saved with the other preferences, and is applied at launch before any window appears, including quiet login startup. Preferences saved before the theme existed keep every saved value and read as System. The menu bar count stays readable in every combination of app theme and macOS appearance. |
| REQ-013 — Quick Add | Settings has a Quick Add section between Appearance and App with an on/off toggle, off by default, for a fixed global shortcut, Control-Option-N. The choice is saved with the other preferences; preferences saved before it existed, or holding an unreadable value for it, read as off and keep every other value. Turning it on registers the shortcut immediately and turning it off unregisters it; it also registers at launch, including quiet login startup without raising a window, and unregisters on Quit. If the system refuses registration, the setting stays on, Settings shows an inline message, the app keeps working, and the next launch or an off/on toggle retries. Settings never claims the shortcut is free of conflicts. Pressing the shortcut from any app shows one reused floating panel, centered on the screen with the pointer, with a focused single-line field; MenuPocket does not become the active app, the Today window is not raised, and the panel can appear over a full-screen app. Return saves trimmed, nonempty text as a new task for the current local day under the same rules as Add task, closes the panel, and updates the menu bar count. Empty input saves nothing and leaves the panel open; a rejected write, or data that became unavailable before Return, keeps the text with an inline error. Escape, Command-W, clicking outside, or pressing the shortcut again closes the panel and discards its text and undo history. The panel supports native text editing and a VoiceOver label; Command-Q, Command-N, and Command-comma do nothing while it is focused. Panel text and errors never change the Today window's drafts, edit or deletion targets, or inline error, except through the existing day-change refresh. When MenuPocket was already active, dismissing the panel returns focus to the previously focused window. If saved data is unavailable, the shortcut tries one refresh and otherwise opens the Today window, which offers Retry. |

## Interaction and recovery rules

Add and edit use single-line fields. Return/Save stores valid trimmed text; Escape/Cancel discards the relevant draft. Completing or uncompleting a task changes its saved checkbox and progress only after persistence succeeds, without moving the row. Completed tasks remain visible in their original positions with muted presentation.

New and current-day edit drafts survive task-window close/reopen within the running process. Add and other row actions cannot replace an active edit. Command-N is unavailable during editing, deletion confirmation, or unavailable data. Quit/relaunch preserves saved tasks but does not promise unsaved-draft recovery.

Quick Add uses the fixed Control-Option-N shortcut; a shortcut recorder is out of scope. It registers exclusively through the system hotkey API and needs no Accessibility or Input Monitoring permission. Only conflicts the system reports can be shown, and while Quick Add holds the shortcut, another app's shared use of the same key stops receiving it. A refused registration leaves the setting on. The capture panel keeps no draft, saves tasks without a category (General), and, once category choices exist, does not change the remembered last-used category. The app keeps its Dock icon and Command-Tab entry (REQ-006) while the panel is shown.

Deletion uses inline confirmation with Cancel initially focused. Cancel/Escape, window close, unavailable data, a changed day, or a removed target cancels confirmation. Confirmation is consumed before writing; a failed delete keeps the row/count and requires fresh confirmation for retry.

A day change cancels stale edit/deletion targets with an explanation and preserves unsaved edit text for recovery. Recovery text is selectable and never saved automatically to another task or day. A new task receives its day assignment when explicitly saved. Retry rereads through the shared daily state.

All app-owned visible and accessibility copy is English, including dates independently of the Mac's language. User-entered text is preserved as entered. Settings provides Open at Login, a Theme choice, the Quick Add switch, app information, and Quit. First explicit presentation completes unfinished onboarding; quiet login startup does not. Existing onboarding completion is preserved.

## Storage and platform constraints

- Preserve bundle identifier `local.menupocket.app` and the sandbox's Application Support `MenuPocket/notes.sqlite`. Use schema v2 with a validated additive upgrade from the known unversioned/v1 task format; never rebuild or vacuum the notes table for this upgrade. Category repository operations persist stable identities/order, normalized unique names, optional task assignments, atomic text/category edits, and all-days removal that preserves tasks and counts. One shared daily state owns the reusable category catalog and publishes categories, today's tasks, and yesterday's count only after every required read and reference check succeeds. Category commands publish only committed changes and keep category field/command errors separate from task drafts/errors. New and edit drafts carry independent category selections that save atomically with their text, survive failures and same-day window reuse, fall back visibly to General (new) or recovery with category context (edit) when the category disappears, and never save a selection outside the catalog. Today groups derive from that snapshot: custom categories in creation order, then General when populated, with tasks in saved order and group counts, including collapsed rows, that sum to daily progress. The category of the last new task saved from Today (not Quick Add, edits, or rejected drafts) and collapsed groups persist in their own defaults keys and fall back to General or expanded. The selector control, grouped checklist, and other interface controls remain a later increment.
- Keep preferences and onboarding markers in their existing `UserDefaults` storage, separate from tasks.
- Retain macOS 14+, SwiftUI/AppKit, App Sandbox, system SQLite, and no account, network service, or third-party dependency.
- Use one app-owned daily state and repository connection. Window presentation and menu bar rendering are consumers, not additional saved-data authorities.
- Verify with the shared `MenuPocket` scheme and isolated fixtures/fakes. Do not seed scenarios by changing the user's tasks or real login registration.

## Scope exclusions

Future-day planning, history browsing, automatic carryover, projects, tags, priorities, deadlines, reminders, recurring tasks, search, filters, sync, accounts, multiple persistent task windows, a second editable menu bar checklist, and a separate background helper remain outside this increment.

Renaming stored `Note` types/tables, unrelated legacy-demo cleanup, saved-task undo/redo, durable unsaved drafts across Quit, public distribution, notarization, and App Store release are also excluded. Native text undo/redo remains supported.

The Quick Add capture panel (REQ-013) does not relax the multiple-task-windows exclusion. It is a transient, single-line entry surface that only adds a task; it does not list, edit, complete, or delete tasks, keeps no draft, and closes after each capture. The Today window remains the only task window.

## Implementation and acceptance status

The task window, CRUD/recovery rules, shared progress, closed-window refresh, native commands, manual/login launch classification, and preservation boundaries are implemented. Task 8's 2026-09-29 regression and local artifact results are retained in the [tracked regression record](DESKTOP_TASK_REGRESSION.md).

Task 9's actual Release report records partial acceptance: window/text/cancellation/Settings/Quit and observed-row relaunch checks passed, while menu bar/Dock and safe-fixture access were blocked and several layout/system checks were not tested. [Desktop acceptance](DESKTOP_TASK_ACCEPTANCE.md) retains those scoped results and the exact remaining gate. Full feature acceptance remains open until the material observations pass against the final artifact.

The Settings theme choice (REQ-012) is implemented with hosted tests for saving, legacy preferences, launch, and live changes. Its running-app results are recorded separately in [Desktop acceptance](DESKTOP_TASK_ACCEPTANCE.md).

Quick Add (REQ-013) is implemented with hosted tests for the saved preference and legacy preferences, registration, refusal, and retry through a fake hotkey service, launch and termination, the unavailable-data fallback, independence from the Today window's drafts and errors, and the capture panel's submit, dismissal, and command keys.

## Historical Notes MVP

The earlier MVP used an icon-only `MenuBarExtra` and compact daily checklist. Its CRUD, failure recovery, SQLite preservation, English copy, Settings, and local-only scope remain the baseline. The desktop task contract supersedes its completion-based ordering, compact-panel, icon-only label, and Settings-first explicit-launch presentation.

The original [Notes MVP regression](NOTES_MVP_REGRESSION.md) and [Notes MVP acceptance](NOTES_MVP_ACCEPTANCE.md) retain their dated results and automation limitations. They do not establish acceptance of the desktop window or native status item. Detailed local plans are linked from the [documentation index](index.md).
