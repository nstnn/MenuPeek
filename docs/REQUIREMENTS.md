# Product requirements

MenuPocket is one local macOS desktop and menu bar app for daily tasks. The desktop increment replaces the compact editable popup with a reusable Today window and menu bar progress; the Later increment adds an undated Later list beside Today in that window. This tracked document defines the product contract without requiring the Git-ignored local plan.

The behavior in the desktop task contract and the rules that follow it is implemented in source. Dated verification results belong in [Desktop regression](DESKTOP_TASK_REGRESSION.md), [Desktop acceptance](DESKTOP_TASK_ACCEPTANCE.md), and the [Later regression](LATER_TASKS_REGRESSION.md) and [Later acceptance](LATER_TASKS_ACCEPTANCE.md) records; implementation, automated verification, and actual system observations are separate claims.

## Desktop task contract

| Requirement | Expected behavior |
| --- | --- |
| REQ-001 — Task window | One resizable task window is reachable from the menu bar and Dock. Repeated presentation restores the same window after closing or minimizing it, including while Settings is open. |
| REQ-002 — Menu bar progress | The saved completed/total count stays visible in the menu bar without an icon while running. A successful empty read shows `0/0`; initial or failed reads show `—`. Successful writes update progress without opening the window; rejected writes retain the last saved count. |
| REQ-003 — Today layout | Show the current local date, progress, grouped tasks, Add task, Manage categories, Settings access, a calendar button that opens [History](#history-unfinished-and-month-calendar--implemented-2026-10-06), and a yesterday reminder when nonzero that opens History at yesterday. Highlight the yesterday reminder in semibold red so unfinished planned tasks are easy to notice. Populated custom categories appear in creation order, then General when populated. Tasks stay in their original creation order within each group; new tasks append to their selected group. Completion, uncompletion, text editing, refresh, and relaunch preserve that order; reassignment uses the task's original relative position in its destination. Deletion closes the gap while keeping the remaining tasks in relative order. Keep empty, all-completed, long-list, long-text, and resized states usable. |
| REQ-004 — Task actions | Add, complete, uncomplete, edit, and delete tasks. Trim input and reject whitespace-only text. Confirm deletion with cancellation available. Publish saved changes only after a successful write; failures retain saved rows/count and recoverable draft text with an inline error. |
| REQ-005 — Daily model | Keep each task's assigned local day. Do not carry unfinished tasks into today. Refresh both surfaces on day, clock, time-zone, and wake changes without requiring an open task window. Unfinished tasks from earlier days are viewable read-only in History; they are not moved, copied, or completed from there. |
| REQ-006 — Lifecycle | Explicit launch, Dock reopening, and a primary menu bar click show tasks. Explicit launch and a menu bar click request Today; Dock reopening restores the retained tab (see [Later contract](#later-contract)). Every native route leaves History; History lives under Today only. The app remains in the Dock and Command-Tab. Closing the last window leaves the process and status item running; Quit exits and removes the item. |
| REQ-007 — Login startup | Preserve the existing launch-at-login registration and Settings control. Login launch initializes daily progress without raising task or Settings windows or requesting activation; the Dock icon remains visible. A genuine login requires separate system observation. |
| REQ-008 — Native interaction | Settings is reachable from the task window and native menu. Support keyboard focus, Return to save, Escape to cancel, Command-N to add, Command-1/Command-2 to select Today/Later, Command-comma for Settings, Command-W to close, Command-Q to quit, and native text editing. Mouse clicks suppress focus outlines on non-text controls throughout Today, category management, Settings, and the retained panels, including after Tab navigation. Tab/Shift-Tab restores visible keyboard focus; subsequent programmatic focus restoration retains that mode. Editable fields keep their native editing focus when clicked. Clicking noninteractive space in the Today window also clears the control focus. |
| REQ-009 — Preservation | Keep existing SQLite tasks, preferences, onboarding state, app identity, and sandbox storage. Category storage introduced additive schema v2, and the Later increment adds additive schema v3: fresh databases and validated unversioned/v1/v2 stores use v3, preserving task UUIDs, rowids/order, text, day keys, timestamps, completion, and counts. Existing tasks have no category association (General); the v3 upgrade adds an empty Later table without rebuilding `notes`. Reject unsupported newer or incompatible schemas without overwriting their data; failed migration rolls back schema, data, and version. |
| REQ-010 — Acceptance | Record automated build/test results separately from actual running-app menu bar, Dock, window, Settings, and system observations. Identify the final source and artifact. Record unavailable checks accurately. |
| REQ-011 — Handoff | Current product/developer docs agree about behavior, scope, implementation, and verification status. Tracked evidence remains understandable without local ignored plans or build artifacts. |
| REQ-012 — Theme | Settings offers System, Light, and Dark in an Appearance section between Startup and App. System is the default and follows the macOS appearance, so an existing install looks unchanged until a choice is made. A choice applies to every app window immediately, is saved with the other preferences, and is applied at launch before any window appears, including quiet login startup. Preferences saved before the theme existed keep every saved value and read as System. The menu bar count stays readable in every combination of app theme and macOS appearance. |
| REQ-013 — Quick Add | Settings has a Quick Add section between Appearance and App with an on/off toggle, off by default, for a fixed global shortcut, Control-Option-N. The choice is saved with the other preferences; preferences saved before it existed, or holding an unreadable value for it, read as off and keep every other value. Turning it on registers the shortcut immediately and turning it off unregisters it; it also registers at launch, including quiet login startup without raising a window, and unregisters on Quit. If the system refuses registration, the setting stays on, Settings shows an inline message, the app keeps working, and the next launch or an off/on toggle retries. Settings never claims the shortcut is free of conflicts. Pressing the shortcut from any app shows one reused floating panel, centered on the screen with the pointer, with a focused single-line field; MenuPocket does not become the active app, the Today window is not raised, and the panel can appear over a full-screen app. Return saves trimmed, nonempty text as a new task for the current local day under the same rules as Add task, closes the panel, and updates the menu bar count. Empty input saves nothing and leaves the panel open; a rejected write, or data that became unavailable before Return, keeps the text with an inline error. Escape, Command-W, clicking outside, or pressing the shortcut again closes the panel and discards its text and undo history. The panel supports native text editing and a VoiceOver label; Command-Q, Command-N, Command-1, Command-2, and Command-comma do nothing while it is focused. Panel text and errors never change the Today window's drafts, edit or deletion targets, or inline error, except through the existing day-change refresh. When MenuPocket was already active, dismissing the panel returns focus to the previously focused window. If saved data is unavailable, the shortcut tries one refresh and otherwise opens the Today window, which offers Retry. |
| REQ-014 — Task categories | Reuse optional custom categories across days, manage them from Today, and save task text/category together. Follow the [category contract](#category-contract) for naming, grouping, preferences, confirmation, and recovery. Existing daily, lifecycle, and preservation rules still apply. |
| REQ-015 — Later list | An always-visible `Today | Later` control in the task window switches to an undated Later checklist of text plus an optional shared category. Later tasks can be added, completed, edited, deleted, and explicitly moved once to Today. Follow the [Later contract](#later-contract). |
| REQ-016 — Menu bar glance | Right-click or Control-click on the menu bar count shows a read-only native menu with the date, Today's progress bar and `N of M done`, up to 5 unfinished Today tasks, an overflow row, an optional `Later · N remaining` line, and Open Today, Add Task… (always to Today), Settings…, and Quit. A primary click is unchanged. Follow the [menu bar glance section](#menu-bar-glance--implemented-2026-10-07). |

## Interaction and recovery rules

Add uses a single-line composer below progress and above the scrollable list. Edit replaces the selected task row with an inline editor for text and category, with Save/Cancel and write errors at that row. The group containing an active edit cannot collapse; the editor stays reachable in long lists. A pending Add draft is hidden during editing and returns unchanged afterward. Category selection does not move the task until Save succeeds. Return in the field or Save stores valid trimmed text; Escape/Cancel discards the relevant draft. Each row has an always-visible native “…” menu with Edit, Move Up, Move Down, Move To (each custom category and General; the current group is checked and unavailable), and Delete…, reachable by mouse or keyboard. Move Up/Down stay within the task's group and are unavailable at its boundaries; Move To appends to the destination. Menu moves use the same saved-move command as dragging, reveal the moved row, and return focus to its menu. Completing or uncompleting a task changes its saved checkbox and progress only after persistence succeeds, without moving the row. Completed tasks remain visible in their original positions with muted presentation.

New and current-day edit drafts survive task-window close/reopen within the running process. Add and other row actions cannot replace an active edit. Command-N is unavailable during editing, deletion confirmation, while the category manager is open, or with unavailable data. Quit/relaunch preserves saved tasks but does not promise unsaved-draft recovery.

Quick Add uses the fixed Control-Option-N shortcut; a shortcut recorder is out of scope. It registers exclusively through the system hotkey API and needs no Accessibility or Input Monitoring permission. Only conflicts the system reports can be shown, and while Quick Add holds the shortcut, another app's shared use of the same key stops receiving it. A refused registration leaves the setting on. The capture panel keeps no draft, saves tasks without a category (General), and, once category choices exist, does not change the remembered last-used category. The app keeps its Dock icon and Command-Tab entry (REQ-006) while the panel is shown.

Deletion uses inline confirmation with Cancel initially focused. Cancel/Escape, window close, unavailable data, a changed day, or a removed target cancels confirmation. Confirmation is consumed before writing; a failed delete keeps the row/count and requires fresh confirmation for retry.

Leaving an edit or deletion returns focus to the task's menu, or its group header when collapsed. If the task disappears, prefer its surviving group, then Add; unavailable data uses Retry. Choosing a category in the composer never saves automatically.

A day change cancels stale edit/deletion targets with an explanation and preserves unsaved edit text for recovery. Recovery text is selectable and never saved automatically to another task or day. A new task receives its day assignment when explicitly saved. Retry rereads through the shared daily state.

All app-owned visible and accessibility copy is English, including dates independently of the Mac's language. User-entered text is preserved as entered. Settings provides Open at Login, a Theme choice, the Quick Add switch, app information, and Quit. First explicit presentation completes unfinished onboarding; quiet login startup does not. Existing onboarding completion is preserved.

## Category contract

Each task belongs to zero or one custom category. General is the built-in fallback for no association (`categoryID == nil`), never a saved category row, and cannot be renamed or removed. Categories are shared across days; task day assignments and yesterday's unfinished count do not change. Categories introduce no carryover. History shows the current catalog: renamed categories show their new name, and tasks of a removed category appear under General. History does not change category preferences.

Custom categories have stable identities and creation order independent of their names. Names are trimmed, nonblank, single-line, and unique under canonical Unicode normalization and case-insensitive comparison with a fixed locale; accents remain significant. General is reserved under that comparison. There is no arbitrary name-length limit; the interface must keep the full name accessible and essential controls usable.

Today shows only populated groups, in custom-category creation order followed by General. Task order within a group follows REQ-003. Each header shows `completed/total` for all its tasks, including collapsed rows; group counts sum to overall daily progress. Collapsing hides rows without changing counts and moves focus from a hidden row to its header. A day with no tasks retains the empty state.

The add/edit Category picker lists every saved custom category in creation order, then General, including when there are no custom categories. Choosing a category does not save. Return/Save stores text and selection atomically; Escape/Cancel retains its existing meaning. Long names truncate in the picker without crowding Save/Cancel at the minimum window size. A successful add, or an edit that changes category, expands its destination; a text-only edit leaves collapse state unchanged.

New and edit drafts have independent category selections. Failed writes and same-day window close/reopen preserve draft text and selection. A pending new draft keeps its selection through repeated Command-N. A genuinely new draft starts with the category of the last successful new-task save from Today, otherwise General. Quick Add, edits, cancellations, and failed writes do not change that remembered choice. Collapsed groups and the remembered category persist in separate defaults keys, outside the existing preferences envelope; missing/malformed choices fall back to General or expanded groups.

If a selected category disappears, a new draft visibly falls back to General; an edit moves its text and category context into recovery. Day changes or missing edit targets likewise preserve recovery context without saving automatically. No draft may save a category outside the completely loaded catalog. Quit/relaunch preserves saved data and presentation choices, without promising unsaved-draft recovery.

Manage categories opens a sheet attached to Today. It lists all custom categories, even those without tasks today, then read-only General. Create/rename show inline validation or write errors; successful rename preserves identity, assignments, and order. The manager can open over a new-task draft without changing it, is unavailable during editing or task deletion confirmation, and blocks task commands while open. Closing Today dismisses it and cancels pending removal.

Removal names the category, reports its task count across **all saved days and Later**, and explains that those tasks move to General without deletion. Cancel starts focused. Cancel/Escape leaves data intact. Confirmation is consumed before writing and rechecks identity/count; a changed count requires another confirmation. A failure preserves the category, assignments, tasks, and counts and requires fresh confirmation. Successful removal preserves task UUIDs, original order, text, day, timestamps, and completion. The long-name confirmation keeps its full name reachable by scrolling while the scope notice and action buttons remain visible.

One shared daily state publishes categories, today's tasks, and yesterday's count only after every required read/reference check succeeds. Category commands publish only committed changes and keep category field/command errors separate from task drafts/errors.

## Later contract

Later means unscheduled work. A Later task's editable content is its text and zero or one existing category; it has no day key, deadline, planned date, calendar, priority, or reminder. Its UUID, creation/completion instants, insertion order, and optional category ID are internal bookkeeping. Saved Later tasks persist across day changes and relaunches.

The task window shows two labeled destinations, Today and Later, whose current selection is visually and accessibly identifiable. Later shows its heading and unfinished count, with no date or progress bar. Groups follow the Today order (custom categories in creation order, then General); groups with only completed rows stay visible with zero remaining. Add, complete/uncomplete, inline text/category edit, and confirmed deletion follow the Today interaction and recovery rules: completion and edits keep position, completed rows stay visible and muted, empty text is rejected, and failed writes retain saved content and recoverable drafts.

Move to Today is offered only for unfinished Later rows. It atomically moves the task once, preserving UUID, text, category, and creation instant; assigns the local day at the moment of the action; and appends it to Today's saved order. The window stays on Later, shows "Moved task to Today.", and restores focus to a surviving row, group, or Add. A failed move leaves both lists unchanged. There is no copy, automatic carryover, reverse move, or move of a completed row.

Menu bar progress is Today-only. Later-only actions never change it; a successful move increases Today's total by one. Categories are shared: renames appear in both tabs, and removal counts and clears assignments in all daily history and Later without deleting any task.

Each tab has its own new-task draft, category selection, composer visibility, write errors, last-used category, and collapsed groups; Later preferences use separate defaults keys and leave the Today keys unchanged. Switching tabs preserves new drafts. An inline edit, deletion confirmation, or the category sheet blocks switching until resolved. Window close/reopen preserves session drafts and the selected tab within the process; a fresh manual launch starts at Today and quiet login stays quiet. A day change does not cancel a Later edit or deletion confirmation.

Command-N adds to the selected tab, or Today without a window. A menu bar click requests Today but cannot discard a guarded Later interaction; the window then comes forward on Later. Quick Add always saves to Today/General without changing either tab's drafts, remembered category, or selection. A Later read failure leaves valid Today progress available, and vice versa; a category catalog or store failure makes both unavailable.

## Storage and platform constraints

- Preserve bundle identifier `local.menupocket.app` and the sandbox's Application Support `MenuPocket/notes.sqlite`. Use schema v3 with validated additive upgrades from the known unversioned/v1/v2 formats; never rebuild or vacuum the notes table for an upgrade. Store Later tasks in a separate `later_tasks` table in the same file and reject version 4+ or incompatible layouts without repair. Older v2 binaries cannot open v3; downgrade is not supported. Persist category identities/order, normalized unique names, optional assignments, atomic text/category edits, and all-days removal under the category contract and REQ-009 preservation rules.
- Keep preferences and onboarding markers in their existing `UserDefaults` storage, separate from tasks.
- Retain macOS 14+, SwiftUI/AppKit, App Sandbox, system SQLite, and no account, network service, or third-party dependency.
- Use one app-owned daily state and repository connection. Window presentation and menu bar rendering are consumers, not additional saved-data authorities.
- Verify with the shared `MenuPocket` scheme and isolated fixtures/fakes. Do not seed scenarios by changing the user's tasks or real login registration.

## Scope exclusions

Future-day planning, dated or scheduled Later tasks, editing or completing tasks on earlier days, moving or copying them into Today, automatic carryover, Today-to-Later moves, projects, tags, priorities, deadlines, reminders, recurring tasks, search, category filters, statistics/streaks, frozen end-of-day history, sync, accounts, multiple persistent task windows, a second editable menu bar checklist, and a separate background helper remain outside this increment.

Renaming stored `Note`/`DailyNotesState` types/tables, bulk task operations, Later completion archive/hiding, unrelated legacy-demo cleanup, saved-task undo/redo, durable unsaved drafts across Quit, public distribution, notarization, and App Store release are also excluded. Native text undo/redo remains supported.

The Quick Add capture panel (REQ-013) does not relax the multiple-task-windows exclusion. It is a transient, single-line entry surface that only adds a task; it does not list, edit, complete, or delete tasks, keeps no draft, and closes after each capture. The Today window remains the only task window.

The [menu bar glance](#menu-bar-glance--implemented-2026-10-07) (REQ-016) does not relax the exclusion of a second editable menu bar checklist. It is a read-only menu that lists up to 5 of Today's unfinished tasks and offers actions that open the task window or Settings, refresh, or quit; it never completes, uncompletes, adds, edits, deletes, or moves a task.

## History, Unfinished, and month calendar — implemented 2026-10-06

History is a read-only child screen of Today in the same retained task window. The calendar button beside Today's date (View task history) opens it with a History heading and Back to Today; it is not a popup, overlay, separate window, or app-wide tab. Unfinished from previous days is reached inside History with Back to History. The yesterday reminder opens History at exactly yesterday with the Unfinished filter, not the all-days Unfinished index.

History defaults to yesterday and its month. A Sunday-first seven-column month calendar, read with one month query, shows each day's date and completed/total count: 0/0 for a loaded past/today day without tasks, — (Not yet) for an empty future day, saved counts for future days that already hold tasks, and Unavailable with month Retry when the month read failed; padding cells are blank and inert. Today is a filled circle and the selection a cell outline, both also named in accessibility labels. Previous month, Next month, and This month change the month (This month selects Today with All); a month change clamps the selected day number to the destination month and selects it only when it is past/today or holds saved tasks. Clicking a cell, or Space/Return on a focused cell, selects it and keeps the current filter; empty future cells do nothing. Arrow keys move focus by day/week and cross into the adjacent month. Windows at least 760 pt wide place detail beside the calendar; narrower windows place it below, scrollable down to the 600 × 400 pt minimum.

Read-only detail shows the date, whole-day completed/total, current category groups with whole-group counts, and tasks in saved order with status images rather than checkboxes; there are no task actions. All/Unfinished/Completed filters change visible rows only, never the counts. Group disclosure is local to the viewed day and does not write Today's category preferences. Empty-day, no-matching-filter, no-selection (Choose a day from the calendar), and unavailable states are distinct; month and day reads each have their own Retry.

Day progress is the number of currently saved tasks assigned to that day with a completion, over all currently saved tasks assigned to it. It does not group by completion date and is not a frozen end-of-day snapshot or productivity score; deleted tasks are not counted, and 0/0 does not prove that no tasks ever existed. Calendar cells, detail, and Unfinished rows use the same definition.

Unfinished lists every day before Today that still has saved unfinished tasks, newest first, 31 days per page with Load more; it pages by day rather than loading all historical tasks. Each row shows its unfinished count and whole-day completed/total. An empty index says there are no saved unfinished tasks before today. Initial and Load more failures have separate messages and Retry; a failed Load more keeps loaded days. Selecting a day opens the shared read-only detail with the Unfinished filter and Back to Unfinished, which returns to the same loaded pages and focuses that row while data is unchanged. If saved data changes so the day no longer qualifies, detail explains it. Go to Today is visible on both Unfinished screens.

Visible panes reread after committed Today/category writes and existing day, clock, time-zone, wake, and activation refreshes; a day change moves the Today marker and Unfinished cutoff while keeping the selected civil day. History read failures never replace Today's data, errors, or drafts. New-task draft text/category/error, composer visibility, and Today scroll position survive child visits within the process. Editing, deletion confirmation, and category management block calendar/yesterday navigation. History is reachable only from the Today tab. Native Show Tasks/menu bar/Dock/explicit launch/Command-N routes target Today in the same window, and Command-1/Command-2 or the title-bar Today/Later control leave History for the selected list; History selection does not affect Today writes or menu-bar progress. History adds no app-wide tabs, additional task windows, schema changes, saved data, or preferences. Relaunch does not promise persistence of unsaved drafts or browser selection.

Status: implemented on `feat/task-history`. Integrated automated verification (TASK-013: full hosted suite 287/287, Debug and Release builds, byte-level preservation, bounded-read timings) is in [Desktop regression](DESKTOP_TASK_REGRESSION.md#2026-10-06--integrated-history-verification-task-013). Final-feature native fixture acceptance (TASK-014) passed every material journey and is recorded in [Desktop acceptance](DESKTOP_TASK_ACCEPTANCE.md#2026-10-06--final-history-feature-native-acceptance-task-014); menu bar/Dock clicks, the real-drag minimum size, and VoiceOver there are user-reported. Not tested natively: a genuine day change, wake, or time-zone change (hosted coverage only), the edit/delete guard UI (hosted coverage), the macOS Keyboard navigation setting, and a production-identity app. Earlier desktop and category acceptance gaps are unchanged.

## Menu bar glance — implemented 2026-10-07

REQ-016 in the [desktop task contract](#desktop-task-contract). The 5-row limit including collapsed groups, enabled task rows, the `EEE d MMM` date and `N of M done` wording, and an accent-colored bar in every state are the implemented choices.

REQ-016 — Menu bar glance. Right-clicking, or Control-clicking, the menu bar count shows a read-only native menu that summarizes Today without opening the task window. A primary click, and a press without a mouse event such as VoiceOver's press action, keep the existing route unchanged (REQ-006): they request Today, leave History, and cannot discard a guarded interaction. No menu stays attached to the status item between glances, so a primary click never opens the glance.

The first item is a non-interactive header that cannot be highlighted, selected, or activated by mouse or keyboard. One line that never wraps shows the date from the saved current day (not the current instant) as `EEE d MMM` in English, for example `Wed 7 Oct`, on the left and `N of M done` on the right. Below them a determinate bar, drawn like the Today window's progress bar (accent fill on a quaternary track, 4 pt high), shows completed / max(total, 1). VoiceOver reads the header as one item, for example "Wednesday 7 October, 4 of 7 tasks done". The Today window keeps its own header and wording.

After a separator, up to 5 unfinished Today tasks follow in the Today window's order (REQ-003 and the [category contract](#category-contract)), including tasks in collapsed groups. The category name appears as secondary text only when today's tasks span more than one group. Long text is truncated with an ellipsis and its full text is the item's tooltip. Rows are enabled; choosing one does the same as Open Today and never writes anything. With more than 5 unfinished tasks, an `N more in Today` row follows and also opens Today. Later tasks are never listed.

When Later has unfinished tasks, a separate section shows one item, `Later · N remaining`, in every Today state; it is absent when the Later count is zero or unavailable. Choosing it opens the window on Later exactly like Command-2: it leaves History, and a guarded interaction brings the window forward without switching. The menu bar count, glance header, bar, and rows stay Today-only (see the [Later contract](#later-contract)); this line is the glance's only Later content.

The last section lists Open Today, Add Task…, Settings…, and Quit MenuPocket in every state, without key-equivalent glyphs. Open Today uses the primary-click route. Add Task… always targets Today, unlike Command-N: it is enabled only when Today's data is available and no inline edit, deletion confirmation, or category manager is active in either tab, and it shows Today with Today's new-task composer. Settings… and Quit MenuPocket match the existing commands. Quit removes the status item and leaves no menu behind; glance actions do nothing after termination begins.

A successful read with no tasks shows `0 of 0 done`, an empty bar, and a disabled `No tasks yet` row. When every task is complete, the header shows `N of N done` with a full bar and a disabled `All done` row. When Today is unavailable (not yet loaded or a failed read), the header shows the date (the current local day when none has been saved yet, as in the task window) and `—` with no bar, followed by a disabled `Tasks are unavailable.` row and an enabled Retry that rereads through the shared daily state; Add Task… is disabled. A Later-only read failure hides only the Later line.

The glance is read-only. Opening, browsing, or dismissing it never writes tasks, categories, or preferences, never changes either tab's drafts, remembered categories, composer visibility, selected tab, History screen, edit or deletion targets, category manager, or inline errors, and never raises a window or activates the app by itself. Only Open Today, Add Task…, Settings…, a task row, the overflow row, and the Later line show a window, through the existing routes.
