# Product requirements

MenuPocket is one local macOS desktop and menu bar app for daily tasks. The desktop increment replaces the compact editable popup with a reusable Today window and menu bar progress; the Later increment adds an undated Later list beside Today in that window. This tracked document defines the product contract without requiring the Git-ignored local plan.

The behavior in the desktop task contract and the rules that follow it is implemented in source. Dated verification results belong in [Desktop regression](DESKTOP_TASK_REGRESSION.md), [Desktop acceptance](DESKTOP_TASK_ACCEPTANCE.md), and the [Later regression](LATER_TASKS_REGRESSION.md) and [Later acceptance](LATER_TASKS_ACCEPTANCE.md) records; implementation, automated verification, and actual system observations are separate claims.

## Desktop task contract

| Requirement | Expected behavior |
| --- | --- |
| REQ-001 — Task window | One resizable task window is reachable from the menu bar and Dock. Repeated presentation restores the same window after closing or minimizing it, including while Settings is open. |
| REQ-002 — Menu bar progress | The saved completed/total count stays visible in the menu bar without an icon while running. A successful empty read shows `0/0`; initial or failed reads show `—`. Successful writes update progress without opening the window; rejected writes retain the last saved count. |
| REQ-003 — Today layout | Show the current local date, progress, grouped tasks, Add task, Manage categories, Settings access, a calendar button that opens [History](#history-unfinished-and-month-calendar--implemented-2026-10-06), and a yesterday reminder when nonzero that opens History at yesterday. Highlight the yesterday reminder in semibold red so unfinished planned tasks are easy to notice. General appears first when populated, followed by populated custom categories in saved rank order. Each day has one saved task order, and each group shows that order filtered to its category. New tasks append to their selected group. Completion, uncompletion, text editing, refresh, and relaunch preserve that order; a category change through Edit keeps the task's place in the day's order, so it appears at that relative position in its destination. Only an explicit move ([REQ-017](#task-movement--implemented-2026-10-07)) changes a task's position. Deletion closes the gap while keeping the remaining tasks in relative order. Keep empty, all-completed, long-list, long-text, and resized states usable. |
| REQ-004 — Task actions | Add, complete, uncomplete, edit, and delete tasks. Trim input and reject whitespace-only text. Confirm deletion with cancellation available. Publish saved changes only after a successful write; failures retain saved rows/count and recoverable draft text with an inline error. |
| REQ-005 — Daily model | Keep each task's assigned local day. Do not carry unfinished tasks into today. Refresh both surfaces on day, clock, time-zone, and wake changes without requiring an open task window. Unfinished tasks from earlier days are viewable read-only in History; they are not moved, copied, or completed from there. |
| REQ-006 — Lifecycle | Explicit launch, Dock reopening, and a primary menu bar click show tasks. Explicit launch and a menu bar click request Today; Dock reopening restores the retained tab (see [Later contract](#later-contract)). Every native route leaves History; History lives under Today only. The app remains in the Dock and Command-Tab. Closing the last window leaves the process and status item running; Quit exits and removes the item. |
| REQ-007 — Login startup | Preserve the existing launch-at-login registration and Settings control. Login launch initializes daily progress without raising task or Settings windows or requesting activation; the Dock icon remains visible. A genuine login requires separate system observation. |
| REQ-008 — Native interaction | Settings is reachable from the task window and native menu. Support keyboard focus, Return to save, Escape to cancel, Command-N to add, Command-1/Command-2 to select Today/Later, Command-comma for Settings, Command-W to close, Command-Q to quit, and native text editing. Mouse clicks suppress focus outlines on non-text controls throughout Today, category management, Settings, and the retained panels, including after Tab navigation. Tab/Shift-Tab restores visible keyboard focus; subsequent programmatic focus restoration retains that mode. Editable fields keep their native editing focus when clicked. Clicking noninteractive space in the Today window also clears the control focus. |
| REQ-009 — Preservation | Keep existing SQLite tasks, preferences, onboarding state, app identity, and sandbox storage. Category storage introduced additive schema v2, the Later increment additive schema v3, and task movement additive schema v4: fresh databases and validated unversioned/v1/v2/v3 stores use v4, preserving task UUIDs, rowids, visible order, text, day keys, timestamps, completion, and counts. Existing tasks have no category association (General); the v3 upgrade adds an empty Later table, and the v4 upgrade gives each day's tasks a saved display order backfilled from their previous rowid order, without rebuilding `notes`. Reject unsupported newer or incompatible schemas without overwriting their data; failed migration rolls back schema, data, and version. |
| REQ-010 — Acceptance | Record automated build/test results separately from actual running-app menu bar, Dock, window, Settings, and system observations. Identify the final source and artifact. Record unavailable checks accurately. |
| REQ-011 — Handoff | Current product/developer docs agree about behavior, scope, implementation, and verification status. Tracked evidence remains understandable without local ignored plans or build artifacts. |
| REQ-012 — Theme | Settings offers System, Light, and Dark in an Appearance section between Startup and App. System is the default and follows the macOS appearance, so an existing install looks unchanged until a choice is made. A choice applies to every app window immediately, is saved with the other preferences, and is applied at launch before any window appears, including quiet login startup. Preferences saved before the theme existed keep every saved value and read as System. The menu bar count stays readable in every combination of app theme and macOS appearance. |
| REQ-013 — Quick Add | Settings has a Quick Add section between Appearance and App with an on/off toggle, off by default, for a fixed global shortcut, Control-Option-N. The choice is saved with the other preferences; preferences saved before it existed, or holding an unreadable value for it, read as off and keep every other value. Turning it on registers the shortcut immediately and turning it off unregisters it; it also registers at launch, including quiet login startup without raising a window, and unregisters on Quit. If the system refuses registration, the setting stays on, Settings shows an inline message, the app keeps working, and the next launch or an off/on toggle retries. Settings never claims the shortcut is free of conflicts. Pressing the shortcut from any app shows one reused floating panel, centered on the screen with the pointer, with a focused single-line field; MenuPocket does not become the active app, the Today window is not raised, and the panel can appear over a full-screen app. Return saves trimmed, nonempty text as a new task for the current local day under the same rules as Add task, closes the panel, and updates the menu bar count. Empty input saves nothing and leaves the panel open; a rejected write, or data that became unavailable before Return, keeps the text with an inline error. Escape, Command-W, clicking outside, or pressing the shortcut again closes the panel and discards its text and undo history. The panel supports native text editing and a VoiceOver label; Command-Q, Command-N, Command-1, Command-2, and Command-comma do nothing while it is focused. Panel text and errors never change the Today window's drafts, edit or deletion targets, or inline error, except through the existing day-change refresh. When MenuPocket was already active, dismissing the panel returns focus to the previously focused window. If saved data is unavailable, the shortcut tries one refresh and otherwise opens the Today window, which offers Retry. |
| REQ-014 — Task categories | Reuse optional custom categories across days, manage them from Today, and save task text/category together. Follow the [category contract](#category-contract) for naming, grouping, preferences, confirmation, and recovery. Existing daily, lifecycle, and preservation rules still apply. |
| REQ-015 — Later list | An always-visible `Today | Later` control in the task window switches to an undated Later checklist of text plus an optional shared category. Later tasks can be added, completed, edited, deleted, and explicitly moved once to Today. Follow the [Later contract](#later-contract). |
| REQ-016 — Menu bar glance | Right-click or Control-click on the menu bar count shows a read-only native menu with the date, Today's progress bar and `N of M done`, up to 5 unfinished Today tasks, an overflow row, an optional `Later · N remaining` line, and Open Today, Add Task… (always to Today), Settings…, and Quit. A primary click is unchanged. Follow the [menu bar glance section](#menu-bar-glance--implemented-2026-10-07). |
| REQ-017 — Task movement | Today tasks can be dragged by a handle, or moved with row-menu Move Up/Down/To, to another position in their group or to another category or General. The day's order and the category change save together and survive relaunch; progress does not change. Follow the [task movement section](#task-movement--implemented-2026-10-07). |
| REQ-018 — Category reordering | Hold and drag a custom category on Today, Later, or in the idle manager to save one global category order, with General fixed first and all task data and collapse choices preserved. Follow the [category reordering contract](#category-reordering-contract). |

## Interaction and recovery rules

Add uses a single-line composer below progress and above the scrollable list. Edit replaces the selected task row with an inline editor for text and category, with Save/Cancel and write errors at that row. The group containing an active edit cannot collapse; the editor stays reachable in long lists. A pending Add draft is hidden during editing and returns unchanged afterward. Category selection does not move the task until Save succeeds. Return in the field or Save stores valid trimmed text; Escape/Cancel discards the relevant draft. Each row has an always-visible native “…” menu with Edit, Move Up, Move Down, Move To (each custom category and General; the current group is checked and unavailable), and Delete…, reachable by mouse or keyboard. Move Up/Down stay within the task's group and are unavailable at its boundaries; Move To appends to the destination. Menu moves use the same saved-move command as dragging, reveal the moved row, and return focus to its menu. Completing or uncompleting a task changes its saved checkbox and progress only after persistence succeeds, without moving the row. Completed tasks remain visible in their saved positions with muted presentation and can be moved like other tasks.

New and current-day edit drafts survive task-window close/reopen within the running process. Add and other row actions cannot replace an active edit. Command-N is unavailable during editing, deletion confirmation, while the category manager is open, or with unavailable data. Quit/relaunch preserves saved tasks but does not promise unsaved-draft recovery.

Quick Add uses the fixed Control-Option-N shortcut; a shortcut recorder is out of scope. It registers exclusively through the system hotkey API and needs no Accessibility or Input Monitoring permission. Only conflicts the system reports can be shown, and while Quick Add holds the shortcut, another app's shared use of the same key stops receiving it. A refused registration leaves the setting on. The capture panel keeps no draft, saves tasks without a category (General), and, once category choices exist, does not change the remembered last-used category. The app keeps its Dock icon and Command-Tab entry (REQ-006) while the panel is shown.

Deletion uses inline confirmation with Cancel initially focused. Cancel/Escape, window close, unavailable data, a changed day, or a removed target cancels confirmation. Confirmation is consumed before writing; a failed delete keeps the row/count and requires fresh confirmation for retry.

Leaving an edit or deletion returns focus to the task's menu, or its group header when collapsed. If the task disappears, prefer its surviving group, then Add; unavailable data uses Retry. Choosing a category in the composer never saves automatically.

A day change cancels stale edit/deletion targets with an explanation and preserves unsaved edit text for recovery. Recovery text is selectable and never saved automatically to another task or day. A new task receives its day assignment when explicitly saved. Retry rereads through the shared daily state.

All app-owned visible and accessibility copy is English, including dates independently of the Mac's language. User-entered text is preserved as entered. Settings provides Open at Login, a Theme choice, the Quick Add switch, a read-only Keyboard Shortcuts section between Quick Add and App, app information, and Quit. The shortcut reference keeps global Quick Add and core app commands visible; More keyboard controls initially collapses the contextual and standard-key reference. Each contextual entry describes where its keys apply. Quick Add's reference reflects off, registered, registration-pending, and refused-registration states without claiming conflict detection beyond the existing service. Key symbols have spoken accessibility equivalents. The reference installs no commands or bindings, changes no stored preferences, and remains reachable by scrolling at the existing Settings minimum size with Quit outside the scroll area. First explicit presentation completes unfinished onboarding; quiet login startup does not. Existing onboarding completion is preserved.

## Category contract

Each task belongs to zero or one custom category. General is the built-in fallback for no association (`categoryID == nil`), never a saved category row, and cannot be renamed or removed. Categories are shared across days; task day assignments and yesterday's unfinished count do not change. Categories introduce no carryover. History shows the current catalog: renamed categories show their new name, and tasks of a removed category appear under General. History does not change category preferences.

Custom categories have stable identities and a saved rank independent of their names. The legacy `creationOrder` property represents this rank, not creation chronology. Names are trimmed, nonblank, single-line, and unique under canonical Unicode normalization and case-insensitive comparison with a fixed locale; accents remain significant. General is reserved under that comparison. There is no arbitrary name-length limit; the interface must keep the full name accessible and essential controls usable.

Today shows only populated groups, with General first and custom categories in saved rank order. Task order within a group follows REQ-003. Each header shows `completed/total` for all its tasks, including collapsed rows; group counts sum to overall daily progress. Collapsing hides rows without changing counts and moves focus from a hidden row to its header. A day with no tasks retains the empty state.

The add/edit Category picker lists General first, then every saved custom category in saved rank order, including unused categories. General remains the only option when there are no custom categories. Up/Down navigation follows this same displayed order. Choosing a category does not save. Return/Save stores text and selection atomically; Escape/Cancel retains its existing meaning. Long names truncate in the picker without crowding Save/Cancel at the minimum window size. A successful add, or an edit that changes category, expands its destination; a text-only edit leaves collapse state unchanged.

New and edit drafts have independent category selections. Failed writes and same-day window close/reopen preserve draft text and selection. A pending new draft keeps its selection through repeated Command-N. A genuinely new draft starts with the category of the last successful new-task save from Today, otherwise General. Quick Add, edits, cancellations, and failed writes do not change that remembered choice. Collapsed groups and the remembered category persist in separate defaults keys, outside the existing preferences envelope; missing/malformed choices fall back to General or expanded groups.

If a selected category disappears, a new draft visibly falls back to General; an edit moves its text and category context into recovery. Day changes or missing edit targets likewise preserve recovery context without saving automatically. No draft may save a category outside the completely loaded catalog. Quit/relaunch preserves saved data and presentation choices, without promising unsaved-draft recovery.

Manage categories opens a sheet attached to Today. It lists read-only General first, then all custom categories in saved rank order, even those without tasks today. Create/rename show inline validation or write errors; successful rename preserves identity, assignments, and order. The manager can open over a new-task draft without changing it, is unavailable during editing or task deletion confirmation, and blocks task commands while open. Closing Today dismisses it and cancels pending removal.

Removal names the category, reports its task count across **all saved days and Later**, and explains that those tasks move to General without deletion. Cancel starts focused. Cancel/Escape leaves data intact. Confirmation is consumed before writing and rechecks identity/count; a changed count requires another confirmation. A failure preserves the category, assignments, tasks, and counts and requires fresh confirmation. Successful removal preserves task UUIDs, saved daily order, text, day, timestamps, and completion; affected daily tasks join General in each day's saved order. The long-name confirmation keeps its full name reachable by scrolling while the scope notice and action buttons remain visible.

One shared daily state publishes categories, today's tasks, and yesterday's count only after every required read/reference check succeeds. Category commands publish only committed changes and keep category field/command errors separate from task drafts/errors.

## Category reordering contract

Today and Later custom-group headers and empty outer padding begin a category drag after at least 4 pt pointer movement, with no hold delay or source highlight. There is no category drag handle. Header press/release below the movement threshold retains disclosure regardless of press duration; crossing the threshold suppresses disclosure even if drag preparation fails. Task text, checkboxes, menus, buttons, and fields retain their existing input. Collapsed categories can move without expanding.

A compact preview shows the name and total task count, including completed tasks. An insertion line at a group boundary proposes before/after placement. Manage categories uses the same gesture on custom labels and their vertical padding, including unused rows, while Rename/Remove and name fields keep ordinary input. Its preview counts assignments across every saved day and Later, once at drag start; a failed count aborts the attempt with the existing usage-read error. Category reordering adds no keyboard commands or Move Up/Down menu. Escape remains cancellation, and existing disclosure, task actions, fields and picker keys remain supported.

One saved custom-category order applies to Today, Later, History day details, Manage categories, Add/Edit pickers, task Move To, and category-group consumers such as menu bar glance. General is fixed first, cannot be a source or a category anchor, and remains the presentation-only group for nil category IDs. Ordinary task screens hide empty groups; pickers and the manager retain General and every custom category. Visible-subset moves use UUID anchors in the complete catalog. For catalog Work/Empty/Personal, Personal before Work saves Personal/Work/Empty; hidden categories retain their relative order. Refresh, window reopen, and quit/relaunch preserve saved ranks.

Start and save both revalidate the complete loaded catalog and visible context. Main-list dragging requires that list to be visible, relevant data available, no edit or removal confirmation, no manager, no termination, and no task drag. Manager dragging requires an idle visible sheet without rename/removal in progress and available category data plus at least one available list. Task and category native drags cannot overlap; invalidation clears authorization while the reservation lasts until native source end. History and glance consume the order without accepting category drags or writes.

Escape, outside release, equivalent placement, stale catalog, or invalid/external input saves no reorder. Failed rank writes or COMMIT roll back the entire move, retain the saved UI order, clear feedback, and show “Could not reorder categories. Try again.” for a fresh attempt. Success, failure, rejection, no-op, and cancellation preserve task UUIDs/text/assignments/rowids/days/timestamps/completion/ranks, Today progress, Later remaining count, drafts/selections, remembered choices, collapse and unrelated preferences. A committed changed move reveals its header or manager row without expanding it. Edge scrolling and feedback stop when the drag is consumed, invalidated, cancelled, or ended.

Only `categories.creation_order` changes atomically through the shared repository under existing schema v4. The legacy Swift `creationOrder` property is a mutable saved rank; unique sparse/negative ranks remain valid on read. A changed reorder may compact the full catalog, but an equivalent move writes nothing. Only committed changed reorders publish the catalog and advance `historyRevision`; no new schema, category table, General row, preference ordering authority, or task UPDATE is introduced. Create still appends, rename keeps rank, and removal keeps survivor order.

Status: implemented with passing final automated regression and an identified isolated native session. Acceptance remains **partial**: required scrolling/reveal, task pointer interaction, some guards/consumers and appearance/system cases are untested or inconclusive. The [category reordering handoff](CATEGORY_REORDERING_HANDOFF.md) owns the evidence, review and remaining gate; these claims do not close earlier category/system acceptance gaps.

## Later contract

Later means unscheduled work. A Later task's editable content is its text and zero or one existing category; it has no day key, deadline, planned date, calendar, priority, or reminder. Its UUID, creation/completion instants, insertion order, and optional category ID are internal bookkeeping. Saved Later tasks persist across day changes and relaunches.

The task window shows two labeled destinations, Today and Later, whose current selection is visually and accessibly identifiable. Later shows its heading and unfinished count, with no date or progress bar. Groups follow the Today order (General first, then custom categories in saved rank order); groups with only completed rows stay visible with zero remaining. Add, complete/uncomplete, inline text/category edit, and confirmed deletion follow the Today interaction and recovery rules: completion and edits keep position, completed rows stay visible and muted, empty text is rejected, and failed writes retain saved content and recoverable drafts.

Move to Today is offered only for unfinished Later rows. It atomically moves the task once, preserving UUID, text, category, and creation instant; assigns the local day at the moment of the action; and appends it to Today's saved order. The window stays on Later, shows "Moved task to Today.", and restores focus to a surviving row, group, or Add. A failed move leaves both lists unchanged. There is no copy, automatic carryover, reverse move, or move of a completed row.

Menu bar progress is Today-only. Later-only actions never change it; a successful move increases Today's total by one. Categories are shared: renames appear in both tabs, and removal counts and clears assignments in all daily history and Later without deleting any task.

Each tab has its own new-task draft, category selection, composer visibility, write errors, last-used category, and collapsed groups; Later preferences use separate defaults keys and leave the Today keys unchanged. Switching tabs preserves new drafts. An inline edit, deletion confirmation, or the category sheet blocks switching until resolved. Window close/reopen preserves session drafts and the selected tab within the process; a fresh manual launch starts at Today and quiet login stays quiet. A day change does not cancel a Later edit or deletion confirmation.

Command-N adds to the selected tab, or Today without a window. A menu bar click requests Today but cannot discard a guarded Later interaction; the window then comes forward on Later. Quick Add always saves to Today/General without changing either tab's drafts, remembered category, or selection. A Later read failure leaves valid Today progress available, and vice versa; a category catalog or store failure makes both unavailable.

## Storage and platform constraints

- Preserve bundle identifier `local.menupocket.app` and the sandbox's Application Support `MenuPocket/notes.sqlite`. Use schema v4 with validated additive upgrades from the known unversioned/v1/v2/v3 formats; never rebuild or vacuum the notes table for an upgrade. Store Later tasks in a separate `later_tasks` table in the same file and each daily task's saved position in integer `notes.display_order`, unique per day. Reject version 5+, incompatible layouts, and invalid saved order without repair. Older v1–v3 binaries cannot open v4; downgrade is not supported. Back up the database before the first real-data launch of a new schema version ([workflow](WORKFLOW.md#schema-v4-upgrade-preparation)). Persist category identities/order, normalized unique names, optional assignments, atomic text/category edits, and all-days removal under the category contract and REQ-009 preservation rules.
- Keep preferences and onboarding markers in their existing `UserDefaults` storage, separate from tasks.
- Retain macOS 14+, SwiftUI/AppKit, App Sandbox, system SQLite, and no account, network service, or third-party dependency.
- Use one app-owned daily state and repository connection. Window presentation and menu bar rendering are consumers, not additional saved-data authorities.
- Verify with the shared `MenuPocket` scheme and isolated fixtures/fakes. Do not seed scenarios by changing the user's tasks or real login registration.

## Scope exclusions

Future-day planning, dated or scheduled Later tasks, editing or completing tasks on earlier days, moving or copying them into Today, automatic carryover, Today-to-Later moves, dragging tasks between days or between Today, Later, and History, reordering individual Later tasks, per-screen/per-day category orders, category nesting, draggable General, multi-task dragging, drag import/export with other apps, board or Kanban layouts, projects, tags, priorities, deadlines, reminders, recurring tasks, search, category filters, statistics/streaks, frozen end-of-day history, sync, accounts, multiple persistent task windows, a second editable menu bar checklist, and a separate background helper remain outside this increment.

Renaming stored `Note`/`DailyNotesState` types/tables, bulk task operations, Later completion archive/hiding, unrelated legacy-demo cleanup, saved-task undo/redo, durable unsaved drafts across Quit, public distribution, notarization, and App Store release are also excluded. Native text undo/redo remains supported.

The Quick Add capture panel (REQ-013) does not relax the multiple-task-windows exclusion. It is a transient, single-line entry surface that only adds a task; it does not list, edit, complete, or delete tasks, keeps no draft, and closes after each capture. The Today window remains the only task window.

The [menu bar glance](#menu-bar-glance--implemented-2026-10-07) (REQ-016) does not relax the exclusion of a second editable menu bar checklist. It is a read-only menu that lists up to 5 of Today's unfinished tasks and offers actions that open the task window or Settings, refresh, or quit; it never completes, uncompletes, adds, edits, deletes, or moves a task.

## History, Unfinished, and month calendar — implemented 2026-10-06

History is a read-only child screen of Today in the same retained task window. The calendar button beside Today's date (View task history) opens it with a History heading and Back to Today; it is not a popup, overlay, separate window, or app-wide tab. Unfinished from previous days is reached inside History with Back to History. The yesterday reminder opens History at exactly yesterday with the Unfinished filter, not the all-days Unfinished index.

History defaults to yesterday and its month. A Sunday-first seven-column month calendar, read with one month query, shows each day's date and completed/total count: 0/0 for a loaded past/today day without tasks, — (Not yet) for an empty future day, saved counts for future days that already hold tasks, and Unavailable with month Retry when the month read failed; padding cells are blank and inert. Today is a filled circle and the selection a cell outline, both also named in accessibility labels. Previous month, Next month, and This month change the month (This month selects Today with All); a month change clamps the selected day number to the destination month and selects it only when it is past/today or holds saved tasks. Clicking a cell, or Space/Return on a focused cell, selects it and keeps the current filter; empty future cells do nothing. Arrow keys move focus by day/week and cross into the adjacent month. Windows at least 760 pt wide place detail beside the calendar; narrower windows place it below, scrollable down to the 600 × 400 pt minimum.

Read-only detail shows the date, whole-day completed/total, current category groups with whole-group counts, and tasks in saved order with status images rather than checkboxes; there are no task actions. All/Unfinished/Completed filters change visible rows only, never the counts. Group disclosure is local to the viewed day and does not write Today's category preferences. Empty-day, no-matching-filter, no-selection (Choose a day from the calendar), and unavailable states are distinct; month and day reads each have their own Retry.

The compact History layout groups Back to Today, the History heading, and the Unfinished entry in one header at wide sizes; the Unfinished entry moves below that header in narrow windows. Month navigation stays above the calendar, alongside This month, with a Selected/Today/count legend below it. The selected day's heading shows its year on a separate line and a View only label. Task rows use a dot or checkmark with a status label, retaining selectable task text and whole-group counts. Day progress is the number of currently saved tasks assigned to that day with a completion, over all currently saved tasks assigned to it. ## Task movement — implemented 2026-10-07

REQ-017 in the [desktop task contract](#desktop-task-contract). Movement applies only to tasks on the Today list. Each assigned day has one saved task order, and groups show that order filtered by category (REQ-003). A task can move within its group or between any custom category and General, including completed tasks. It stays the same task: its UUID, text, assigned day, creation instant, and completion are unchanged; only its category and position change. Moving never changes daily or menu bar progress, though group counts follow the new assignment. It never changes either draft or the remembered category for new tasks.

Each Today row has a subdued six-dot handle before its checkbox, with the tooltip "Drag to move task" and the accessibility label "Move task: <text>". Only the handle starts a drag, after a small movement. The checkbox, selectable text, and “…” menu keep their native behavior. The drag shows a compact task-shaped preview and is a local move only: other apps receive nothing, and the window accepts no text, files, or drags from elsewhere. Dropping on the upper or lower half of a row places the task before or after it, shown by an insertion line. Dropping on a group header, or on the footer at the bottom of a group ("Move to end of group", or "Drop task here" in an empty group), places it at the end of that group, shown by an accent highlight. While a valid drag is in progress, empty custom categories and General appear in their normal order as temporary destinations. Collapsed headers accept drops without expanding on hover. A position equivalent to the current one, including the task itself, offers no target and writes nothing. Near the top or bottom edge of the list, the list scrolls at a bounded rate. Escape, releasing outside the window or away from a target, and closing the window cancel the drag without writing, and temporary groups and feedback disappear.

The row's “…” menu is the keyboard-accessible alternative: Move Up and Move Down stay within the group and are unavailable at its boundaries, and Move To lists each custom category and General, with the current group checked and unavailable, and places the task at the end of the chosen group ([interaction rules](#interaction-and-recovery-rules)).

Every route builds the same request from stable identities: the task's UUID, its displayed day and group, the destination group, and a placement before or after another task's UUID or at the end of the group. It never uses visible indices or text. One saved-move command checks the request against the current data again at save time. The category change and every affected position commit together. A rejected, stale, or equivalent request writes nothing. After a successful move, the destination group expands and the moved task is revealed; after a menu move, focus returns to that row's menu, and pointer drops do not show a keyboard focus ring. A failed write keeps the saved list, both drafts, and collapse choices, clears drag feedback, and shows "Could not move task. Try again."

Moving is unavailable, and an in-progress drop is refused, during an inline edit, deletion confirmation, or category management, with unavailable data, after termination begins, or when the displayed day is no longer Today. These guards are checked again when the drop or menu action completes. A pending new-task draft may stay open during a drag and is unchanged. Selecting Later, opening History, starting a new task, requesting a deletion, or closing the window cancels an active drag and any pending reveal.

Other writes keep the saved order. Add, Quick Add, and Later's Move to Today append to the end of the day, and so to the end of their group. Completion and edits keep a task's position, including a category change through Edit. Deletion keeps the remaining order. Renaming a category changes no order, and removing one merges its tasks into General in each day's saved order. History detail and the menu bar glance list tasks in this saved order. Schema v4 stores the order (see [storage constraints](#storage-and-platform-constraints)).
